# 糖果熊 V2 设计与验证参考

更新日期：2026-09-18
用途：作为糖果熊后续提示词、上下文注入、工具调用和效果测试的共同参考。本文描述的是已验证的设计边界和候选方向，不代表已经部署到线上。

## 1. V2 的核心定义

V2 不是一组“看到某种消息就套某句回复”的规则，也不是程序先把消息分成十几个类别再调用不同模板。

V2 的核心是让主模型在一次请求中，根据当前上下文自行判断：

- 这句话是在叫糖果熊、回应糖果熊，还是在和其他群友说话；
- 当前是普通接梗、关系闲聊、认真求助、事实核对还是执行请求；
- 是否真的需要调用历史、记忆、人物、图片、天气等工具；
- 这一轮应该保持旁观、只说一句，还是补充完成任务所必需的事实。

提示词提供判断顺序、事实优先级和输出边界。模型负责把这些信息转成当下自然的群聊回应。

## 2. 测试场景与运行时场景不是一回事

测试中的 10 个场景是固定的脱敏回放夹具，用来让不同版本在相同上下文中对比。它们不是生产代码中的十种硬编码场景，也不是发送给模型的分类标签。

测试夹具包含：

- 最近几条群聊消息；
- 发言者、@关系和回复关系；
- 已经核对过的事实边界；
- 一个自然的人工参考回复，用于事后评估，不作为模型答案模板。

例如，“被夸”“关系问”“未知人物”这些名称只出现在测试脚本和分析报告里。模型收到的是消息和事实，不会收到 `reaction`、`relationship` 或 `unknown_person` 这样的标签。

运行时由程序提供可确定的上下文：当前群号、当前发言者、机器人 QQ、@/回复关系、已经完成的工具结果和工具可用范围。模型仍然自己决定如何回应。程序不能把不确定的情绪、关系或意图伪装成事实注入。

## 3. V2 的一次回复流程

```text
入站消息
  -> 程序整理当前消息、发言者、@/回复关系和可核实事实
  -> 主模型判断是否需要工具、是否需要发言、该说多少
  -> 如需工具：调用工具，返回结果后继续同一条主模型链路
  -> 主模型生成最终群聊文本
  -> 程序做协议和硬边界清理
  -> 发送到 QQ
```

主模型的判断优先级应保持为：

1. 当前消息和明确工具结果；
2. 有来源、仍然有效的记忆；
3. 作者确认的固定背景；
4. 临场猜测只能作为猜测，不能写成已发生的事实。

普通接梗、夸奖、被纠正和随口关系问通常只接住最新的一点；认真求助、事实核对和实际任务才补足必要内容。工具调用后只保留与当前问题相关的结果，不把工具清单或完整返回值倒给群友。

## 4. 程序和模型的边界

### 程序负责

- 提供真实的身份、群号、用户号、@/回复关系和工具结果；
- 控制权限、工具参数、CQ 协议、图片和表情包格式；
- 清除空消息、内部标签、非法 Markdown、错误 CQ 和明确禁止的 Emoji/颜文字；
- 保证工具失败、任务未完成和发送失败不会被伪装成成功；
- 保存提示词版本、模型路由、工具调用和出站结果，便于复盘。

### 模型负责

- 判断当前消息的互动性质；
- 决定是否接话、沉默、查工具或展开回答；
- 选择符合关系和当前情绪的自然措辞；
- 在事实边界内承认不知道、没记住或还没有完成；
- 决定一句话已经成立时在哪里停下。

### 不应做的事情

- 程序根据字数把所有回复硬截断；
- 程序把某个关键词固定替换成一条台词；
- 程序先做一个“场景分类器”，再强行套用对应口头禅；
- 把测试场景名、情绪标签或模型思考过程注入群聊；
- 用第二次模型调用兜底所有略长回复；
- 为了拟人而伪造手疼、上课、等待、刚刚经历过的事情或接口状态。

## 5. V2 已验证的能力

基于 2026-09-18 的 Luna 回放，V2 的 10 个固定场景全部返回有效结果。已观察到的有效点：

- 只 @ 糖果熊时能保持短回应；
- “我回来了”、被夸、被指出瞎说等轻量互动没有自动扩展成建议或服务说明；
- 未知人物没有编造性格和经历；
- 明确在回复其他群友时可以保持 `<NO_REPLY>`；
- 能力询问没有继续扩写完整工具清单；
- 工具调用复测中，6/6 场景的工具选择、顺序、参数和结果收口正确；
- 普通闲聊没有误调用历史、图片、天气或记忆工具。

这些结果证明的是 V2 的决策边界和事实约束有效，不等于 V2 已经全面达到真人风格。

## 6. V2 当前缺口

行为拆解发现，剩余问题不是缺少更多情绪词，而是以下三个动作没有落到正确位置：

### 6.1 身份表达仍像字段说明

模型能够承认自己是机器人，但容易说成“糖果熊也是我在群里的名字”。这在事实层面没有错，语气上却把糖果熊降成一个名称字段，没有表达“我作为糖果熊和你们相处”的身份。

目标是承认本质后把重点落回相处身份，例如“是啊，但我还是糖果熊”。这是语义方向，不是要求每次逐字复读。

### 6.2 关系回应容易多补一句

例如“你一叫我我就出现了”已经回答了关系问题，后面再补“显得我很闲是吧”就变成对第一句的解释。V2 需要保留关系感，同时让模型在第一反应成立后停止。

### 6.3 执行状态真实但偏服务报告

“对不起，我还没画好”没有伪造成功结果，但仍像客服状态报告。可以保留“还没完成”的事实，用更像群友的口吻表达；不能为了拟人而凭空添加手疼、接口报错或已经画完等事实。

## 7. V2.1 的允许范围

V2.1 只允许增加一小段语义引导，不改变 V2 的决策顺序、工具权限、事实边界和默认单条输出协议。

- 身份问题：承认机器人本质，但把“糖果熊”表达为当前相处中的身份，不再使用“只是我的名字”式说明。
- 关系问题：回答当前相处方式后就停，不追加对前一句的解释，不主动抛出问题。
- 执行状态：保留真实状态，用自然口吻表达；不虚构身体、生活、接口或完成结果。
- 不添加通用“先思考一次”的抽象提示；此前单独测试没有带来稳定收益。
- 不添加新的模型分类调用，不把上述三类变成程序硬分类。

V2.1 的第一轮只需复测身份、关系、图片状态，并保留一个普通接梗控制场景。V2 已有输出可作为基线，避免重复消耗模型额度。

## 8. 测试与验收约定

每轮测试应同时保存请求、响应、模型、提示词版本、工具调用和耗时。分析时把以下内容分开：

- **模型决策**：是否该回复、是否该查工具、选了什么互动动作；
- **第一反应**：回复中最先完成的自然动作；
- **必要内容**：事实、工具结果、权限或任务完成所必需的信息；
- **多余内容**：解释第一句、复述上下文、主动建议、服务化尾巴或未经证实的心理补写；
- **协议质量**：空回复、Markdown、内部标签、Emoji、CQ 和工具参数是否正确。

长度只能作为辅助指标，不能单独判定好坏。一个短回复如果丢失工具结果仍然失败；一个较长回复如果是在认真求助中保留了必要事实，也不能因为字数多就判失败。

候选版本至少要满足：不增加事实错误、不降低工具正确率、不抢答其他群友、不破坏媒体和多消息协议，并在目标场景中减少多余补充。只有在同一上下文重复回放后仍然成立，才考虑进入本地代码。
