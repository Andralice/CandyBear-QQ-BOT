# 糖果熊按需加载：首批实现与验证

日期：2026-09-16。范围：本地实现与验证，未部署、未调用付费模型。

## 行为

常用工具和核心规则持续提供。图片创作、视频、语音、群内数值游戏、三角洲、洛克王国、聚会游戏分为七个可组合的能力包。默认提示保留短能力目录，避免模型把“本轮未提供工具”误认为“没有这项能力”。

明确请求直接预加载，不增加分类模型调用。附图编辑同时兼容主模型图片输入和旧 Vision 文字描述路径；普通看图仍使用原有图片理解工具。游戏进行中的状态可为裸数字等消息加载游戏规则。

同一会话、同一用户最近五分钟的能力选择用于识别续接，最多保存 512 个条目。它只影响预加载，不代表任务已执行、图片已确认或记忆事实。普通插话不会删除或延长原线索的有效期；“刚才那张”等有指代的续接可以参考它，“好的／可以／确认／继续”等单独短句不自动认定所属任务，由主模型结合上下文判断。清空会话会清除线索，服务重启后不保留。

群聊和私聊主入口分别传递当前用户原话与附件状态，预加载不扫描拼入的引用、Vision 描述、网页摘要。完整资料仍保留给主模型理解与查询。用户引用别人的作品并要求参与时，模型可以根据回复关系加载能力，不会继承另一个群员的个人线索。原图选择仍必须经过图片查询与校验。旧入口未提供独立原话时，兼容原输入；未命中的表达由模型使用 `load_capabilities` 补充加载。

加载操作只申请能力，不执行功能。整批工具结果返回后，才同时更新系统规则和工具 schema。模型在同一批里“加载语音 + 直接发语音”，后者会因本轮未公开而被拒绝，需下一轮重新调用。若模型直接调用未加载但已注册的工具，明确返回对应能力的加载入口；禁用或未授权工具不会因此变成可加载。已公开工具在本次生成内保持可用，查询图片与生成图片复用同一实例，保持图片编号有效。

生图预加载时就注入完整调用规范，省去专门索取规范的一轮；原有资料摘要、参考图编号、旧图确认等校验保留。旧模式直接调用未加载规范的生图工具，仍只返回规范，不提交任务。

## 自定义规则兼容

存在非空 `system_prompt_override`、`rule_book`、`rule_tool` 或 `rule_game` 时，保守回退到完整工具和规则，保留原先生图规范握手，不自动拆解已有自定义文本。这些配置未迁移时，不会获得完整按需加载收益。

默认规则按结构拆分，新增可逐条覆盖的规则名为 `voice`、`game_social`、`game_delta`、`game_lokowang`；原 `game` 对应聚会游戏。其他人设、事实、隐私、图片理解规则仍走现有构建器。旧覆盖不会被静默删除，`tool_desc_*` 仍在首次与后续请求生效。首批以外的工具仍采用原加载方式。

能力目录只从已注册的工具构建；关闭 Agnes 时目录没有图片/视频生成，也不能通过加载器取回。加载器不能添加管理员工具或绕过工具自身的权限校验。

## 验证

- 复杂场景补充后的全量 `mvn -q package`：371 项，326 通过，45 跳过，0 失败、0 错误。跳过项需要 `RUN_DB_TESTS` 或真实服务环境。
- `mvn -q -DskipTests package` 与 `git diff --check` 通过；已确认 JAR 包含能力加载类及生图规则资源。
- `CapabilityToolsTest`：13 个测试方法，包括组合请求、闲聊精简、两条图片输入路径、续接与跨用户隔离、五名群员交错、引用及附件资料隔离、过期与容量、活动游戏、禁用能力、加载原子性与幂等、旧规则兼容、OpenAI/Anthropic 规则和 schema 同步更新、完整工具结果顺序。
- `ImageGenerationWorkflowTest`：9 项，通过本地 HTTP 服务验证图片查询到提交链路；新增验证预加载无提交副作用、首次真实调用可生成、补充加载保留原图编号和前置校验。没有向真实 QQ 或 Agnes 发送内容。
- 其余既有协议、画像、记忆、消息与模型池测试随全量回归运行。

字符对照使用固定普通用户上下文，基线包含全部默认规则；不包含线上群成员列表和动态历史。初版系统提示对照从 10,258 到 8,616 字符（约 16%），后续补充复杂场景边界后以测试日志 `CAPABILITY_SIZE` 为准。工具 schema 对照是 17 个工具的局部测试注册表，其中数据库工具使用替身，不能外推为完整生产请求的比例。

这是结构、协议与本地模拟验证，不是真实模型行为验收，也不能据此承诺响应秒数。未预加载的能力需要额外一轮加载；关键词误命中只多提供规则，不会自动操作。线上仍应观察加载日志中的选择、工具数、提示长度，以及真实首条可见消息延迟、工具轮数和能力漏用情况。

日志关键字：`能力加载`、`能力补充加载`。首批不涉及队列、重试、全量群成员上下文或其他性能改造。

## 复杂场景补充检查

新增五名群员交错的确定性回放：不同用户分别涉及画图、语音、三角洲、洛克、天气；原请求者临时闲聊后返回，确认不会混入别人的能力，其他群员也可通过加载器加入公共话题。另外验证引用旧请求、图片中的文字、网页摘要不会触发当前原话的预加载，保留资料让主模型理解；明确附图编辑仍能直接加载。

这些回放验证程序的选择与恢复机制，没有模拟主模型的真实理解结果。以下不能据此视为已解决：

- 同一用户同时有多个任务，“再来一个”到底指哪个，需要主模型读取上下文；能力线索不是任务状态机，也不携带确认或图片归属。
- 取消、否定、改需求可能仍命中预加载，但不能因此执行。执行意图由主模型决定，不靠额外否定词正则替代语义判断。
- 检查当前调用流程发现，群聊是在 `generate(session)` 返回后检查新增消息并决定是否重新生成；在工具执行期间到达的取消或修改不保证能阻止已经开始的外部操作。需要单独处理执行前版本检查及已经提交任务的取消能力，当前补丁没有声称解决这一点。
- 超时不等于失败、重新生成不等于允许重复提交；实际副作用是否重复仍需调用链与任务编号验收。
- 真实模型能否在漏预加载时主动加载，是否误执行、误认原图，以及多人插话后的自然程度，需要少量真实模型或线上受控场景验收。
