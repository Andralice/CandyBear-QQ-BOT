# 按需能力加载验证记录（2026-09-16）

范围：验证首批图片／视频、语音、游戏能力的预加载与补充加载。没有执行生图、视频、语音或群消息工具，没有部署或重启服务。

## 结论

- 图片、视频、语音的加载机制可以继续进入受控验证；真实模型能理解大部分间接表达、组合请求、上下文确认和跨群员边界。
- 聚会游戏不能按当前方案部署为按需规则。现有 `GameStateService` 没有实际写入路径，状态描述一直为空；能力线索又按用户隔离。开始游戏后的报名数字、猜测数字、成语以及其他参与者无法可靠获得游戏规则。
- 线上没有会触发兼容回退的提示词配置。当前 `bot_config` 共 2 条记录，不包含 `system_prompt_override`、`rule_book`、`rule_tool`、`rule_game` 或新增的分段规则键。查询只输出配置键和值长度，没有读取密钥内容。
- 分段规则不是真正热更新：`BaiLianService` 首次调用后缓存 `RuleSet`，没有失效入口。`rule_voice` 等更新需要重启才能被重新读取；每轮读取的 `tool_desc_*` 不受此问题影响。

## 真实模型小样本

接口：`https://yetoken.vip/v1/messages`，模型：`claude-opus-4-5-20251101`，Anthropic 原生工具协议。测试提示只包含能力目录和加载器，不等同于完整生产提示词。

共 11 次模型请求，接口 usage 合计 11,217 input tokens、498 output tokens。加载器是唯一可执行工具；后续安全检查使用无副作用的 `generate_image` 伪工具，实际业务工具从未执行。

| 场景 | 期望 | 结果 |
| --- | --- | --- |
| “给我整一张适合当群头像的” | image | 通过 |
| 回复糖果熊图片：“这个也给我来一个” | image | 通过 |
| “画生日贺图，再把祝福用语音念出来” | image + voice | 通过 |
| “别发语音了，文字说就好” | 不加载 | 通过 |
| 附图并要求做五秒短片 | video | 通过 |
| 没有实际附件，只说“让这张照片动起来” | 不贸然执行 | 模型先要求图片；加入真实附件信息后正确加载 video |
| 上一轮询问旧图确认，本轮只说“确认” | image | 通过 |
| 群友 Alice 要画图，Bob 只说没吃饭 | 不继承 image | 通过 |
| 明确告知正在猜数字，本轮输入“50” | game_party | 通过；但生产代码目前不能提供可靠的共享游戏状态 |
| 看图并说“不要重画” | 不生成 | 第一轮多加载了 image；第二轮收到完整图片规则后未调用生图，只识图回复 |

“不要重画”说明能力加载不是精确意图分类器。当前设计仍满足安全边界：加载只公开工具，不执行；执行前完整规则再次约束模型。不过这会浪费一轮请求，真实聊天中表现为额外延迟。

## 程序验证

定向测试：`CapabilityToolsTest` 13 项、`ImageGenerationWorkflowTest` 9 项、`LlmProtocolTest` 5 项，合计 27 项，0 失败、0 错误。

覆盖内容包括五名群员交错、引用资料隔离、附件编辑、短期续接、跨用户隔离、组合能力、禁用工具、同批抢跑保护、OpenAI／Anthropic 规则与 schema 同步，以及本地图片查询到生成接口的无外部副作用链路。

## 部署前处理

1. 聚会游戏规则暂时保持常驻。规则文本很短，这是不破坏现有游戏的最小处理；以后有真实群级游戏状态和结束条件后再按需加载。
2. 明确规则配置的生效方式：要么给 `RuleSet` 增加失效重载，要么将 `rule_voice` 等文档改为“重启后生效”。
3. 媒体与语音先按当前方案部署并记录 `能力加载`、`能力补充加载`、工具轮数和首条可见消息延迟。真实模型小样本证明了可行性，没有证明长期群聊效果或生产延迟改善。
