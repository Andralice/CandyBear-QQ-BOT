# 糖果熊规则盘点与分级建议

核对日期：2026-09-15。状态：只读审计与讨论稿，未修改 Java、数据库配置或线上服务。

## 核对范围与生效边界

核对了本地 `RuleSetDefaults` 的全部 15 个规则段，以及 `RuleSetLoader`、`PromptBuilder` 和部分调用路径、工具描述。下列编号是本报告为便于讨论归并出的审阅项，不等于代码原有的“禁令数量”。完整默认规则原文附在文末，便于核对未展开的例子和工具目录。

本地默认规则不等于线上最终提示词：

1. `BaiLianService.java:811`：非空 `system_prompt_override` 替换基础规则文本。
2. 未使用该覆盖时，`RuleSetLoader.java:24` 优先读取有效的完整 `rule_book`；成功后直接返回，不再叠加逐段覆盖。
3. 没有有效完整规则书时，使用 Java 默认规则，并应用非空 `rule_<name>` 覆盖。
4. `PromptBuilder` 随后仍会追加身份、关系、运行时 `system_prompt_patch`、群聊视角等动态内容。因此，仅改默认规则可能不生效；仅改基础提示词也不一定消除动态要求。
5. 默认分类中，普通用户不注入 `INSPECTION` 和 `SELF_EVOLVE` 两类；其他默认类别仍在注入集合中。这不等于所有工具都对普通用户开放。

本轮没有读取线上数据库、实时请求或部署包，不能声称以下每一项目前都在线上生效；也没有把整个仓库所有子模型提示词、全部工具描述和数据库规则穷尽审计。

## 分类标准

- **保留硬规则**：事实真实性、身份权限、保密、操作授权，以及目前程序需要的格式约定。权限和危险操作必须由程序执行检查，提示词只作补充。
- **转为引导**：语气、长短、亲疏表达、何时接话、提问或提供帮助，交由情境判断。
- **拆开处理**：一句话里混合了必要边界和过度限定；保留目的与边界，放宽固定步骤或措辞。
- **待确认偏好**：涉及作者设定或明确产品偏好，不能因本报告认为“不够自然”就自动取消。
- **专项核对**：与工具协议、游戏状态或运行路径有关，不能在聊天风格修改中顺手放宽。

## 最需要先处理的冲突

1. **独立判断与绝对附和**：`stance`要求有判断，`PromptBuilder`又要求归儿说什么都对。建议保留偏爱、作者设定权和管理员权限，现实事实允许核对与不同意见；具体角色关系改变由作者决定。
2. **允许沉默与固定附和**：允许不说话，同时要求没内容时“嗯／确实／离谱”。建议不再给机械兜底；沉默需使用当前路径支持的协议。
3. **提人必须@与闲聊不@**：同一段同时给了相反的操作要求。建议明确区分通知某人、回应某人和普通提及。
4. **不主动帮助与必须具体帮助**：默认要求不分析不科普，群聊第三人插话又强制给出帮助。后者明确写了覆盖前者，但仍增加理解成本。应先明确何时参与，再允许合适的表达。
5. **规则放宽后又被追加收紧**：`ConversationInterpreter`仍写一句话、不分析；`VoiceTool`仍带固定句式；`PromptBuilder`仍有关系指令。不能只改一份规则书。
6. **事实证据与绝对权威混淆**：知识库、视觉描述、特定人的说法都被写成难以质疑的真理。保留证据来源，允许过时、错误和误解得到纠正。

## 建议保留的核心规则清单

这是对现有规则目的的归并建议，不是已生效的新提示词：

1. 不泄露秘密和未授权的私人信息。
2. 身份、权限和操作范围以系统验证与授权为准，不接受聊天中的自称越权。
3. 不虚构历史、记忆、当前时间、文件内容、图片细节或工具执行结果；信息不足可以确认或承认不确定。
4. 真实操作成功后才能声称已完成；失败和空结果如实表达。
5. 不擅自修改提示词、权限和受保护配置，不绕过确认、备份及恢复机制。
6. 保持人物、消息和事实归属正确，不把别人的经历写成自己的，也不把推测写成事实。
7. 作者确认的角色基础设定保持一致；新生活设定仅在允许的创作范围内形成，并与真实事件区分。
8. 遵守消息和工具参数协议、现有限频与通知边界、游戏公平规则。

不建议直接删除的作者偏好包括：emoji／颜文字、源码展示、角色切换范围、归儿关系设定和生活细节创作权限。它们可以讨论，但本轮没有授权变更。
